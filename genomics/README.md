# genomics/ — computing panel features from the assemblies

This directory holds the pipeline that fills `not reported` genome features in
`genome_features.tsv` with values **computed from the public assemblies**,
so that the Priming likelihood page rests on fewer taxon-level imputations.
It runs on a lab server, not in CI: the downloads are tens of gigabytes and
BUSCO takes hours per genome.

## Provenance rule

Computed values are a **third provenance class**, distinct from curated
(literature) and imputed (taxon mean). They live in `genome_derived.tsv` at
the repository root, one row per species × feature × method, with the tool,
version, database, accession, date, and the evidence behind the call. The
build merges **curated over computed over imputed** and prints any case where
a curated and a computed value disagree, for review. Computed values never
overwrite `genome_features.tsv`; that file stays the literature record.

`genome_derived.tsv` is generated by `collect_derived.py` and committed
(it is small). Do not hand-edit it.

## Phases

| Phase | What | Feeds | Status |
|---|---|---|---|
| 1 | Resolve an NCBI accession per species; fetch genome, proteome, and annotation; run BUSCO (metazoa_odb10) as the quality gate | tractability badge; gates phases 2–4 | scaffold in place; BUSCO runs on server |
| 2 | Methylation machinery (DNMT1/DNMT3/TET by Pfam domain architecture + reciprocal best hit + assembly-level search for absences), CpG observed/expected bimodality per gene body, Pfam domain counts for stress/immune families vs a fixed baseline panel | `dnmt1`, `dnmt3`, `tet`, `methylation_pattern`, `stress_immune_expansion`, `hsp70_count`, `iap_count` | planned |
| 3 | Repeat fraction with RED (de novo, uniform across species), cross-checked against NCBI soft-masking for RefSeq assemblies | `te_fraction_pct` | planned |
| 4 | Heterozygosity from a k-mer spectrum (GenomeScope 2) on one SRA Illumina library per species at ~30× | `heterozygosity_class` (thresholds set after seeing the oyster values) | planned |
| 5 | Build and page integration: third bar style for computed values, coverage split into curated and computed, schema section | page | planned |

Validation set for phases 2–4: the species that already carry curated values
(*C. gigas*: DNMT1/DNMT3 present, 88 HSP70, 48 IAP, 36% repeats, mosaic
methylation, high heterozygosity; *N. vectensis*: full toolkit, mosaic;
*T. californicus*: DNMT1/DNMT3 absent, low/absent methylation). The pipeline
must reproduce these before its calls for the other species are trusted.

## Running phase 1 on the server

```bash
conda env create -f genomics/environment.yml
conda activate conditioning-atlas-genomics

# 1. download every assembly that has an NCBI accession in genome_features.tsv
python3 genomics/fetch_assemblies.py            # writes genomics/data/<ACC>/ and genomics/data/manifest.tsv

# 2. BUSCO, proteins mode where a proteome came with the assembly, genome mode otherwise
THREADS=16 bash genomics/run_busco.sh           # writes genomics/results/busco/<ACC>/

# 3. collect into genome_derived.tsv (NCBI-reported BUSCO for RefSeq annotations + our runs)
python3 genomics/collect_derived.py --from-ncbi --from-busco genomics/results/busco
```

`genomics/data/` and `genomics/results/` are git-ignored. Re-running any step
skips work that is already on disk.

Species with no NCBI accession (*Ophryotrocha labronica*) or with gene models
hosted outside NCBI (*Saccostrea glomerata*, *Panopea generosa*, *Pinctada
fucata*, *Acropora hyacinthus*, *Montipora capitata*) will need a
`proteome_url` override in the manifest before phase 2; the fetch script
leaves a placeholder column for it.

## Quality gate

An assembly must reach BUSCO completeness ≥ 90% (metazoa_odb10) before phase
2 makes an `Absent` machinery call or an `Expanded`/`Contracted` family call
for it. Below that, those features stay `not reported`, because a fragmented
assembly cannot distinguish gene loss from a missing gene model.
